# Workflow 05 — Implementation and Quality

## Before coding
- Read relevant requirements, stories, decisions, repository instructions, and tests.
- Confirm scope and acceptance criteria.
- Inspect existing code and follow project conventions.
- Ask before destructive, externally visible, costly, or permission-expanding actions when project policy requires it.

## During coding
- Prefer small, reviewable changes.
- Add or update tests alongside behavior changes.
- Avoid unrelated refactors.
- Do not weaken security controls or tests to make a build pass.
- Report blocked work and newly discovered assumptions.

## Before marking complete
- Run relevant tests and builds when available.
- Verify each acceptance criterion with evidence.
- Review security, error handling, accessibility, performance, and documentation as relevant.
- Summarize files changed, checks run, results, limitations, and remaining risks.
- Update requirement-to-test traceability.
